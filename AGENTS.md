# Artificer contribution instructions

## Scope and truth

Read `README.md` and all files in `docs/` before proposing implementation.
The reviewed first source slice contains original neutral fixtures and a
single-card editor/MCP pipeline. Old prototype assets and private preservation
history remain excluded. Read `docs/first-slice.md` before changing its boundaries.

Distinguish verified implementation, recovered historical intent, current product
requirements, and new proposals. Historical foundation checkboxes are reports,
not proof of current behavior. Do not call planned features implemented or select
an architecture silently.

MCP is a core requirement. Agents must author within explicit template, text-fit,
widow, symbol-placement, alternate-art exception, bleed, print, and special-frame
rules. Resolve hard rejection, warning, automatic repair and override policy
before implementation. Preview and validation must preserve designer intent.

## Preservation and coordination

Preserve dirty/untracked source and existing records; inspect repository identity,
status, remotes, refs and worktrees before source work. Work in isolation and do
not alter unrelated projects. Tracker choice remains open. Do not migrate/delete
trackers, rewrite historical records, deploy, change permissions, create
credentials, or begin broad redesign without the requested direction discussion.

Recovered OpenSpec notes describe existing conventions and planned phases.
The old prototype and bundled skills are not included here. Inspect current
source instructions and evidence before applying recovered conventions. Keep application UI design separate from card-template
output design. Mobbin and Open Design research are inputs, not approved patterns
or dependencies.

## Native interaction tests

Read [native test process](docs/native-testing.md) before any native UI input.
Obtain a coordinated foreground slot and use disposable synthetic projects.
User activity takes priority over an earlier test slot. Check the unlocked
session, exact live process/window and actual foreground before every input
batch. An intended window, DOM focus or successful activation request is not
proof of the event recipient.

Use an input route explicitly scoped to the verified process/window. Do not
fall back to global HID posting or other unscoped input when delivery is
unverified. Stop on unknown target/focus, changed ownership or inconclusive
delivery; preserve evidence and report the precise missing prerequisite.
Do not broaden the route, repeat stalled probes, change permissions, or inject
cleanup keys into another app. Record event times/routes and balanced key pairs,
then verify observable UI and disk outcomes. Emitted keys alone are not a pass.
Close the controlled test app safely and explicitly release the slot.

## Delivery and review

The owner approved the reviewed public documentation-only bootstrap. Subsequent
authorized changes use scoped reviewed PRs. The owner approved this clean source
slice with original neutral fixtures.
Do not publish the preserved prototype, its unattributed assets or its ancestry.
The owner selected A+C: card workbench plus explicit proposal-review treatment.
Read `docs/workbench.md`; keep initial acceptance authority and single-card scope.
No project license has been selected.

Desktop/local-first Tauri and dense TCG/LCG cards are selected. Compatible stable
dependency upgrades and the architecture in `docs/first-slice.md` are approved.
Larger library/service alternatives and expanding filesystem or MCP authority
require explicit design.

All subsequent integration, including documentation/design, must use a scoped PR
with substantive independent adversarial review. Review the actual complete
patch and relevant evidence; challenge feature claims, authority and preservation.
Fix findings and recheck the final diff. Standing scoped-merge approval does not
resolve missing product decisions or authorize deployment.

For documentation changes, check relative links, Markdown formatting, full-tree
publication scope, and Git ancestry. Do not add tests that merely mirror prose.
Use the source commands in `README.md`; old recovery checks in
`docs/verification.md` describe the preserved prototype. For executable changes,
run native regressions,
actual browser/MCP acceptance, publication-tree/ancestry checks and independent
adversarial review. Do not accept mock width estimates as text-fit evidence.
Documentation-only process changes require independent review, link/format and
publication/ancestry checks; they do not authorize native input or require a
repeat of completed source suites. Preserve incident evidence outside the public
tree and keep verified, failed and unverified outcomes distinct.
